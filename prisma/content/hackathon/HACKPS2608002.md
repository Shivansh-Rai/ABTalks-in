Build the interviewer, not the interview.

## The Situation

The ABTalks AI Cohort is running right now: thirty-one days of enterprise AI engineering for working professionals in the US. RAG pipelines, embeddings and vector databases, agentic systems with MCP, evaluation and governance, containerised deploys. People arrive with real careers behind them and leave with production-shaped AI work in front of them.

They finish, they enter the recruiter portal, and then someone senior asks them to defend the RAG pipeline they built on day 12. That conversation is the one thing the programme doesn't rehearse - and unlike a student, this candidate is being interviewed as a professional who claims thirty-one days of production AI work *on top of* a decade of career. The bar is higher and the questions are sharper.

Build the rehearsal.

## Ship at Minimum

- An agent that runs a **multi-turn technical interview**, not a quiz, a conversation. **Minimum: at least 8 questions spanning at least 4 distinct curriculum days.**
- Questions **grounded in the curriculum**. Every question should trace back to a day this candidate actually did - the day, its objectives, its tools. "Tell me about a challenging project" is a failure; "walk me through why you locked that system prompt over the other four variants" is the job.
- Questions that **adapt to the previous answer**, including following up when an answer is thin. *Example: candidate says "I used embeddings to make the search better" → non-adaptive agent moves to the next scripted question; adaptive agent asks "better how - recall, latency, relevance? What did you measure it against?"*
- A close that produces **specific, structured feedback** - what was strong, what was vague, what to do next. **`strengths`, `gaps`, and `next` are each arrays of short strings (one point per item), not free text.**

## What We're Looking At

- Whether it **probes**. An agent that accepts "I used embeddings to make the search better" and moves on has failed.
- Whether it **reads the record** - a candidate who needed four attempts at retrieval and one at everything else should not get the same interview as one who breezed through.
- Whether the feedback is specific enough to **change what someone does tomorrow**.
- How it handles the candidate who **doesn't know** - bluffing, silence, or "the assistant wrote that part."
- Whether a senior engineer with nine years behind them would feel this was **worth their evening**. That's a higher bar than impressing a student.
- *(Judging note, not a hard scope line): one role done well beats a menu of twelve.*

## What You're Given

Two files. The first is the **entire cohort curriculum** - all thirty-one days as they are actually taught right now, with every day's objectives and toolchain:

```json
curriculum.json
{ "cohort": "AI Cohort · 31 days · 8 modules",
  "modules": [ { "n": 6, "title": "Agentic AI & MCP", "days": [21,24] }, … ],
  "days": [
    { "day": 22, "title": "Multi-Agent Orchestration",
      "type": "SHIP_IT", "tools": ["CrewAI", "LangGraph"],
      "objectives": [
        "Install CrewAI or LangGraph for multi-agent orchestration",
        "Define Router, Coverage Specialist and Claims Specialist agents",
        "Wire routing so the Router picks which specialist runs",
        "Compare 5-question results to Day 21, document when multi-agent helps"
      ] },
    … 30 more
  ] }
```

Read those objectives again - that is what makes this brief possible. An agent holding them doesn't have to invent plausible AI questions; it can ask *"you wired a Router in front of a Coverage and a Claims specialist - how did the Router decide which one ran, and what did you do when it picked wrong?"* **Real curriculum, real ground truth.**

The second file is the person sitting the interview:

```json
candidate.json
{ "member": { "jobRole": "Senior Data Engineer", "yearsExperience": 9,
              "education": "MS, Computer Science", "status": "COMPLETED" },
  "missions": [
    { "day": 8, "title": "Vector Databases Overview", "passed": true },
    { "day": 12, "title": "Prompt Engineering Fundamentals",
      "passed": true, "attempts": 4 },
    { "day": 22, "title": "Multi-Agent Orchestration", "passed": true },
    { "day": 29, "title": "Kubernetes - Orchestrating & Scaling", "skipped": true },
    … 27 more
  ],
  "signals": { "commitDays": 24, "missionsFirstTry": 19 } }
```

**The person is invented; the curriculum is real.** Nobody's data is used, so there is nothing to consent to and nothing to leak - and yet every question your agent asks lands on genuine production AI work.

Note what the record hands you: day 12 took **four attempts**, and day 29 was **skipped entirely**. A weak agent asks "explain RAG." A good one notices that this candidate never deployed to Kubernetes and asks what happened. **The gaps are in there on purpose.**

- Same two files for every team.
- Accepting a **pasted public GitHub URL** as a third source is welcome. Not required. **If provided, treat it as an additional grounding source for questions - e.g., pull actual code/config to ask about specific implementation choices - not just a link displayed for context.**

## How You Submit It

Build whatever interface you like - that's what the judges will use. But your agent must **also** be reachable at one plain HTTP endpoint, so it can be interviewed automatically. The candidate arrives on the opening call:

```http
# opening call - carries the candidate, no "message" yet
# sessionId is generated by the caller (judge's test harness) and passed in;
# your endpoint should accept it as given, not mint its own.
POST /api/interview
{ "sessionId": "abc-123", "candidate": { …candidate.json… } }

# every turn after that
{ "sessionId": "abc-123", "message": "I'd use a hash map here." }

# every turn comes back the same shape
{ "reply": "Why a hash map and not a sorted array?", "done": false }

# the final turn carries the feedback
{ "reply": "That's the end of the interview.",
  "done": true,
  "feedback": { "summary": "...", "strengths": [], "gaps": [], "next": [] } }
```

No auth, JSON in and out. It's one route wrapping the logic you already wrote, and it's the difference between us being able to evaluate your agent properly and having to guess from a screenshot - see verifying an agent.

## Out of Scope

- Voice. Text is completely fine.
- Accounts, history, saved sessions.
- Breadth of topics.
